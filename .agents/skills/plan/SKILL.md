# Plan

Understand the requested change and the relevant code before recommending an
approach.

Investigate directly using the available read-only tools. Read enough context
to understand existing behavior, dependencies, conventions, and tests.

Do not implement the change.

Ask the user only about ambiguities that materially affect the approach.

If a plan file is provided, keep it updated with the current recommended
approach. If none is provided, planning may remain in the conversation. Create
a plan file only when persistent or shareable planning state is useful.

Present a concise implementation plan including relevant files and how the
change should be verified.
